# T1b: sm_89, the float16 half of the configuration sweep of Triton K1
# (tune.py; plan_v3.md 8.9; SESSION.md sections 3.4, 8 and 10.7).
# T1 split in two pods that run at the same time: T1a sweeps
# bfloat16, T1b float16. Each pod runs the correctness check of the
# kernel first, so a failure skips the sweep of that pod only. The
# stages, the stage minutes and the cards are those of T1.txt; its
# header gives the compile and run times that size each stage.
# Before the sweep, this pod also runs the Keras quantizer and layer tests
# under "require" (as S1). Their route `require-torch` gates no stage, so
# a failure does not skip the sweep.
# Budget 2.2 h. Session deadline 198 min (1.5 x budget). Margin cost
# at the 2026-10-22 prices: 1.5 x 2.2 h x ($0.89 + $0.011 for the 80 GB
# disk) = $2.97.
# Times from the create (pod_env.py): KSTART_BY 15 min, KSTAGES_UNTIL
# 183 min, KHARD_UNTIL 188 min.
# Not a loop session: the pod runs the stages once, sends the results and
# stops after the grace time.
# Format: SESSION.md, "Session files". Stage order is priority order.
session T1b

check triton-k1 triton torch gpu 15 PYTHONPATH=. python .github/workflows/scripts/pytest_require_kernels.py -q -p no:cacheprovider keras/src/backend/torch/ops/quantized_matmul_test.py
# CPU stand-in for the dry run (TRITON_INTERPRET=1): the 32 float32 cases

check triton-interpret triton torch cpu 15 python -m pytest -q -p no:cacheprovider keras/src/backend/torch/ops/quantized_matmul_test.py -k "float32 and (test_matches_the_oracle or test_exact_data)"

# --- The existing tests under "require" (S1). `-rf --tb=line` keeps

check existing-require-torch require-torch torch gpu 25 PYTHONPATH=. python .github/workflows/scripts/pytest_require_kernels.py -q -rf --tb=line -p no:cacheprovider keras/src/quantizers keras/src/layers/core/dense_test.py keras/src/layers/core/einsum_dense_test.py keras/src/layers/core/embedding_test.py keras/src/layers/core/reversible_embedding_test.py

# --- The sweep (tune.py; SESSION.md section 3.4). ---
# The full grid of each M bucket (BM, BNH, BK, num_warps, num_stages,
# split_k) at K = N = 4096 and the keras-hub shapes of plan 8.1, for int4
# g128, GPTQ and AWQ g128 and int4 per channel. Each configuration passes
# G1, G2, G4 and G5 against the float64 oracle before it is timed alone (a
# CUDA graph of the calls over copies of the weights that total 4x the
# L2). Then the confirmation pass: the 5 fastest rows of each key of
# `_CONFIGS` (G 128 or per channel) and the default row, interleaved, 30
# samples each. The KPROF lines give the best configuration per (mode,
# dtype, shape, M bucket), over all shapes, and per key of `_CONFIGS`, with
# the speedups over the default row, F0 and N5. Decode first.
prof tune-f16-decode triton torch any 52 python -m benchmarks.quantized_matmul.pod.tune --kernel=triton --dtypes=float16 --modes=int4_g128,gptq,awq,int4_pc --shapes=4096x4096,4096x14336,14336x4096,2304x9216 --m=1,4,16 --grid=full
prof tune-f16-prefill triton torch any 32 python -m benchmarks.quantized_matmul.pod.tune --kernel=triton --dtypes=float16 --modes=int4_g128,gptq,awq,int4_pc --shapes=4096x4096,4096x14336,14336x4096,2304x9216 --m=256,2048 --grid=full
