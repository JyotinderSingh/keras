# T1: sm_89, the configuration sweep of Triton K1 (tune.py; plan_v3.md 8.9;
# SESSION.md sections 3.4 and 8). The sm_89 rows of `_CONFIGS` come from it.
# Cards: RTX 4090 secure $0.89; RTX 4090 community $0.34. No other card: the
# rows of the table key on the compute capability only, and the sm_89 rows
# target the RTX 4090 (128 SMs, 72 MB L2). tune.py writes the card name into
# each record and into the summary. Check it before a row goes into the
# table.
# Budget 3.2 h. Session deadline 288 min (1.5 x budget). Margin cost at the
# 2026-10-22 prices: 1.5 x 3.2 h x ($0.89 + $0.011 for the 80 GB disk) =
# $4.32 (community: $1.68).
# Times from the create (pod_env.py): KSTART_BY 15 min, KSTAGES_UNTIL 273 min,
# KHARD_UNTIL 278 min.
# Not a loop session: the pod runs the stages once, sends the results and
# stops after the grace time.
# Stage minutes, from the compile and run times of 2026-10-22
# (quant-tooling/kernels/probes/tune/):
# - Compile. Triton 3.8.0 compiles `_w4a16_kernel` for sm_89 in 0.78 s per
#   kernel on a sample of the decode grid (1.05 s grouped, 0.5 s per
#   channel) and 1.7 s on the prefill grid, on one Apple CPU core in
#   Docker. The estimate takes a pod CPU core as 1.5 x slower. A decode
#   configuration has 15 kernels (M = 1, 4 and 16 specialize; signed and
#   unsigned codes; the 18 groups of K = 2304 are not a multiple of 16):
#   about 21 CPU-s. So 576 configurations take about 25 min on 8 workers.
#   A prefill configuration has 5 kernels (M = 256 and 2048 use the same
#   kernels): 432 configurations take about 11 min, in the first prefill
#   slice.
# - Run. About 25 ms per decode measurement (the checks, the capture, and
#   11 replays of a CUDA graph of the R calls). 20 ms (M = 256) to 120 ms
#   (M = 2048) per prefill measurement (35 calls).
# - The compile workers get at most half of the time that is left. Decode:
#   2 x 25 min = 50 min, + 2 min. Prefill: the M = 256 slice compiles and
#   measures in about 15 min; the M = 2048 slice measures in about 16 min;
#   + 2 min. Each slice has its own deadline (tune.py). A stage that runs
#   out of time has measured an even sample of the grid; its `slice` lines
#   give the share.
# Results: about 85,000 records, 1,000 to 1,400 chunks: about 2 min of reads
# at 800 chunks per minute. grace_s 300 is more than 2 x that.
# Format: SESSION.md, "Session files". Stage order is priority order.

# --- The sweep (tune.py; SESSION.md section 3.4). ---
# The full grid of each M bucket (BM, BNH, BK, num_warps, num_stages,
# split_k) at K = N = 4096 and the keras-hub shapes of plan 8.1, for int4
# g128, GPTQ and AWQ g128 and int4 per channel. Each configuration passes
# G1, G2, G4 and G5 against the float64 oracle before it is timed alone (a
# CUDA graph of the calls over copies of the weights that total 4x the
# L2). Then the confirmation pass: the 5 fastest rows of each key of
# `_CONFIGS` (G 128 or per channel) and the default row, interleaved, 30
# samples each. The KPROF lines give the best configuration per (mode,
# dtype, shape, M bucket), over all shapes, and per key of `_CONFIGS`, with
# the speedups over the default row, F0 and N5. Decode first.
prof tune-bf16-decode triton torch any 52 python -m benchmarks.quantized_matmul.pod.tune --kernel=triton --dtypes=bfloat16 --modes=int4_g128,gptq,awq,int4_pc --shapes=4096x4096,4096x14336,14336x4096,2304x9216 --m=1,4,16 --grid=full
prof tune-f16-decode triton torch any 52 python -m benchmarks.quantized_matmul.pod.tune --kernel=triton --dtypes=float16 --modes=int4_g128,gptq,awq,int4_pc --shapes=4096x4096,4096x14336,14336x4096,2304x9216 --m=1,4,16 --grid=full
prof tune-bf16-prefill triton torch any 32 python -m benchmarks.quantized_matmul.pod.tune --kernel=triton --dtypes=bfloat16 --modes=int4_g128,gptq,awq,int4_pc --shapes=4096x4096,4096x14336,14336x4096,2304x9216 --m=256,2048 --grid=full
prof tune-f16-prefill triton torch any 32 python -m benchmarks.quantized_matmul.pod.tune --kernel=triton --dtypes=float16 --modes=int4_g128,gptq,awq,int4_pc --shapes=4096x4096,4096x14336,14336x4096,2304x9216 --m=256,2048 --grid=full
